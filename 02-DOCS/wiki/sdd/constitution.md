# sonofile — Constitution

Ratified 2026-11-01 · last amended 2026-11-01 · v1.0.0

## Known facts (from onboarding)

- Goal: A music library automatic manager
- Project kind: software · scope: growing
- Changes land through branches closed with a pull request; the default branch is closed to direct work.

## 1. Stack canon

1. The project is a Python command-line application (CLI). Tags are read and written with `mutagen`.
2. Environment and dependencies are managed with `uv`; the Python version is pinned in `pyproject.toml`.

## 2. Quality bar

3. `ruff` (lint and format) and `mypy --strict` pass with zero errors.
4. `pytest` passes with line coverage ≥ 80 %.
5. Every behaviour change ships with tests written first (red → green → refactor).

## 3. Conventions

6. Commits follow Conventional Commits.
7. CLI errors go to stderr and exit with a non-zero code.

## 4. Branching & shipping

8. Branches are named `feat/`, `fix/` or `chore/`.
9. `main` receives no direct changes. Every change enters through a PR with green CI, merged by squash.
10. Git authorship is the human's: no `Co-Authored-By` an AI and no "generated with" footer. Enforced at `ship`.

## 5. Security & privacy floor

11. Every operation that modifies music files is dry-run by default.
12. No file is deleted or overwritten without explicit confirmation and a record that allows undoing it.
13. No secret is committed. Library data never leaves the user's machine without explicit consent.

## 6. UX / accessibility floor

14. CLI output never relies on colour alone. `--help` is complete and `--json` gives machine-readable output.

## 7. Performance budgets

15. No numeric budget until measured on a real library. A scan never loads the whole library into memory.

## 8. Knowledge & decisions

16. Every significant decision is appended to `02-DOCS/wiki/sdd/decisions.md` with date, options and why.

## Definition of Done (the merge bar `verify` runs against)

- CI is green: `ruff`, `mypy --strict` and `pytest` with coverage ≥ 80 %.
- Any file-modifying behaviour has its dry-run path tested.
- Documentation and `decisions.md` are updated.
- The PR is reviewed and squash-merged.
